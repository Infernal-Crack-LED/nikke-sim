# Handoff — extend the DPS rank system to B1 and B2 units

> Context-packed for a fresh session (owner: plan + implement there). The four
> non-DPS boards landed 2026-07-26 (burst-gen, burst-CDR, sustain, buffer) —
> most of the discovery for THIS task was done during that work and is
> condensed here. Read `docs/data/rank-boards.md` first for what landed.

## The ask

The DPS chart (`scripts/build-dpschart.ts` → `web/public/dpschart.json`,
frameworks in `src/dpschart/matrix.ts`) ranks B3 carries only. Extend it (or a
sibling board) so B1 and B2 units get DPS ranks too.

## What gates the population to B3 today

`scripts/build-dpschart.ts:80-87` — three independent gates:

1. `if (c.burst !== 'III') continue;` — the B3-only filter. Side effect: it also
   excludes `red-hood` (burst `Λ`), the roster's only Λ unit.
2. `c.generatorSupported && c.simSupported` — enikk-proven + a hand-tuned
   override exists.
3. `data/bossing-tiers.json` tier ∈ SSS–B — **carry-oriented tiers**; B1/B2
   supports mostly have no meaningful bossing tier, so this gate needs a
   replacement or removal for the new population.

## The framework-shape problem (the real work)

All five matrix frameworks assume the tested unit is a **B3 carry**
(`src/dpschart/matrix.ts:246-305`): named-control comps put the tested unit in
slot 0 as the leftmost B3; the Solo framework puts it in slot 3 with
`burstGate: 'everyOther'` so it alternates the stage-3 cast with the no-op B3.
A tested B1/B2 breaks every one of these comps — there is no tested-B3 to carry
the stage-3 cast at all.

**The buffer board (landed 2026-07-26) already solves this exact shape** —
reuse it: `src/ranks/buffer.ts` `assemble()` builds
`[tested-B1, no-op B2, carry-mg, carry-rl]` / `[no-op B1, tested-B2, …]` /
`[no-op B1, no-op B2, carry-mg, carry-rl, tested-B3-rightmost]`. For a B1/B2
**DPS** board the same comp works unchanged; just score `units[testedIdx].dps`
instead of the carry-sum delta. Options:

- **A. Own-damage solo-style board (recommended starting point).** B1/B2 unit in
  the buffer-board comp shape, ranked by its OWN dps. Caveat: its number then
  includes buffs it receives from nobody (only itself) — a pure isolation
  number, directly comparable across units. This is the Solo-framework
  philosophy transplanted.
- **B. Full matrix extension.** Add B1/B2-tested framework variants to
  `src/dpschart/matrix.ts` (named supports filling the other stages: liter or
  little-mermaid B1, crown B2, helm + tested-or-filler B3). Much bigger blast
  radius: new cells × axes, precompute time, web tab changes. Only if the owner
  wants Prydwen-style team-context DPS for supports.

## Practical notes

- Synthetic infrastructure already exists: `src/ranks/synthetics.ts`
  (`carryWithWeapon`, modal stats, `syntheticFor`), no-op controls
  `src/dpschart/noop.ts`, gauge rows in `data/gauge-per-shot.json`.
- Population for a B1/B2 DPS board: `simSupported && burst ∈ {I,II}` ≈ 60-70
  units (the buffer board's population minus the B3-buffer-tagged, plus nothing
  else). `red-hood` needs an explicit decision (Λ; the generator force-pins her
  to B3 — `effBurst` in `scripts/tests/lib/harness.ts:275`).
- B1/B2 units' own damage is small; expect the board to be dominated by
  hybrid dps-supports (nayuta, mast-romantic-maid, grave). Whether the owner
  wants raw own-damage or own-damage-in-a-standard-team (receives crown/liter
  buffs) is THE methodology question to settle first — option A vs B above.
- The 12/12-tier OL optimizer (`src/dpschart/run.ts` `optimizedLines`) assumes
  the tested unit is the damage focus — reusable as-is for B1/B2 tested units.
- Artifact shape for a new board: mirror `scripts/build-burstgen.ts` (leanest
  of the four new builders).
